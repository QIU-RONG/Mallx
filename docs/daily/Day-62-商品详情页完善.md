> 需求原话：**「完善商品详情页」**。
> 这一轮只动 C 端详情页，不加新接口 —— 全部用现有数据（商品详情 / 评价 / 商品列表）。

## 0. 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 面包屑 | 分类只是文字 | 分类可点，带 `categoryId` 回列表 |

## 1. 为什么是这几项

详情页的完成度主要看三件事：**信息是否齐全、下一步是否明确、有没有退路**。

- 面包屑和「相关推荐」是**退路**：看完这件不买，有地方去；
- 评价锚点解决**决策信息太远**：评价在整页最底部，价格区要能一键跳过去；
- 服务/配送说明是**成交前的顾虑**，比再放一句营销文案有用。

## 2. 一个做了一半又撤回的改动

本来想把「已下架规格」置灰。查后端 `SkuVO` 发现**它没有上下架字段**
（只有 id / skuCode / name / price / originalPrice / attributes / image）——
库存与状态都在 inventory 域，详情接口不返回。

⇒ 没有数据支撑的「已下架」只能靠猜。撤回该分支，把注释留在样式里：
等哪天后端在 `SkuVO` 补 `status`，这一段直接恢复即可。

★ 这是本轮唯一一次「设计稿写了、实现时被数据模型否掉」的地方 —— 记下来，
免得下次有人重新踩一遍。

## 4. 没做的

1. **主图放大 / 轮播**：现在只有点击缩略图切换；全屏预览等有真实商品图再说（占位图放大没意义）；
2. **库存显示与限购**：详情接口不返回库存，需要后端补字段或单独查库存接口；
3. **规格与库存联动**（选中规格显示剩余件数）：同上；
4. **优惠券入口**：详情页没有「领券」位，属于营销域，需要另一个接口聚合可用券。
