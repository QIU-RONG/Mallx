# Day 65 · 我的订单列表改版（以商品为主体）

> 用户截图：订单列表整屏都是 `MX2026...` 单号（还折成两行），并说 **「这里也要改」**。
> 延续 Day 63 的同一判断：顾客认商品，不认订单号。

---

## 0. 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 列表主体 | 订单号（折行）+ 状态 + 金额 + 收货人 + 时间 | 商品缩略图 + 商品名 + 规格 +「等 N 件」+ 金额 + 时间 |
| 订单号 | 首列，很长、还会折行 | 移出列表（订单详情里仍保留，客服对账不受影响） |
| 收货人 | 列表列 | 移出列表（详情页有；列表不需要「寄给谁」） |
| 操作 | 表格右侧一列 | 每张卡片底部一行链接（详情 / 支付 / 取消 / 确认收货） |

## 1. 数据从哪来（这次不走前端 N+1）

Day 63 概览页只有 3 单，前端并发查详情可以接受；但订单列表一页 10 条，
再 N+1 就是 10 次详情请求 —— 不行。

所以 **后端补字段**：

- `OrderVO` 增加 `firstItemName / firstItemSkuName / firstItemImage / itemCount`；
- `OrderServiceImpl#listMyOrders` 在分页之后，用**一次 `IN (orderIds)`** 查出本页所有明细，
  内存分组取首件，不做 N+1；
- 排序仍按 `createdAt DESC, id DESC`（同日多单靠 id 兜底）。

★ 代价：OrderVO 变胖了一点。可接受 —— 它只多 3 个字符串 + 1 个整数，
换掉「列表上看不到买的是什么」。

## 2. 验证

| 项 | 结果 |
|---|---|
| 主链路 e2e | **40 / 40** |
| 接口实测 | 首页 3 单均返回 `firstItemName=Apple iPhone 17 Pro`、`firstItemSkuName=黑色 256GB`、`itemCount=1` |
| 页面截图 | 商品图 / 名称 / 规格 / 金额 / 状态 / 详情链接均正常，单号不再出现 |
| lint / build | 通过 |

## 3. 没做的

1. **一单多商品只显示首件**（显示「等 N 件」），展开多件属于详情页；
2. 管理端订单列表仍是单号视角（对账场景保留单号合理）；
3. 没有缩略图时仍走 `ProductThumb` 的字母兜底。
