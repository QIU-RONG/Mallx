## 1. 为什么只做展示层

「商户模块」有三种量级（见 Day 64 讨论）：

1. **店铺展示层**：商品属于哪家店，页面显示出来，后台能维护店铺；
2. **商户后台**：商户账号登录，只能看自己店的商品/订单（每张表按 shop_id 过滤 + 新角色）；
3. **交易闭环**：入驻审核、拆单、分账、商户侧售后。

本次选 ①。②③ 不是「加几张表」，而是把**数据权限**和**交易链路**同时改一遍：
订单要按店拆、支付要分账、售后要按店隔离，涉及 order/payment/inventory/aftersale 四个模块。
先把「这家店是谁」讲清楚，才有资格谈后面两件事。

## 2. 数据与权限

```sql
shops(id, name UNIQUE, logo, description, status, created_at, updated_at)
ALTER TABLE products ADD COLUMN shop_id BIGINT REFERENCES shops(id);  -- 可空
```

- `shop_id` **可空**：历史商品允许「未归属」，不做 NOT NULL 强绑；
- 停用店铺**不影响商品归属**，也不隐藏商品（本轮只记录状态；要在 C 端隐藏需另做口径并处理详情缓存）；
- 店名 UNIQUE → 重名返回 **400 人话**（不能把 23505 冒成 500）。

权限只发超管：改店名/停用店铺等于改整个店铺门面，与「禁用账号」同级别的治理动作。
反向对照：`op_product` 打 `GET /api/admin/shops` 是 **403**。

## 3. 界面

**管理端**：列表（含停用）、新建、编辑、停用/启用。没有删除 —— 店铺下可能挂着商品，
物理删会让历史商品失去归属说明；不用时停用即可。

**C 端**：商品详情标题下方的店铺胶囊（SVG 店铺图标 + 店名）。
没有店铺的商品**不显示**，不编一个「平台自营」。停用店铺的商品仍显示店名（归属事实不因停用而改变）。

## 4. 途中踩的坑

1. **`mvn package` 不重建 jar**：类改了、`BUILD SUCCESS`、但 jar 时间戳没变，
   启动后新字段/新接口全没有。判定方法：看 jar 的 `LastWriteTime`。
   ⇒ 用 `mvn clean package` 强制重建（本项目不是第一次在这上面浪费时间）。
2. **测试 JVM 被 OOM 杀掉**：机器上还挂着十几个 headless Edge，surefire 报
   `The forked VM terminated without properly saying goodbye` + dumpstream 里的
   `insufficient memory`。杀掉 headless 浏览器后重跑即绿 —— 失败原因是内存，不是测试。
3. **e2e 的权限总数硬编码 48**：新增 3 条权限后 `day56-local-e2e.py` 的 A.10 变红。
   这与 Day 55 的教训同源：**权限总数每变一次，所有断言它的地方都要跟着变**；
   `day47-perm-count-guard` 只覆盖了 5 处「常量声明点」，验收脚本里的字面量是第 6 类，
   本轮已改为 51 并写清注释。

## 6. 没做的（按第 1 层的边界）

1. **商户账号与登录**：没有 `merchants` 表、没有商户角色；
2. **数据隔离**：管理端所有列表仍是平台全量视角，没有按 shop 过滤；
3. **商品表单选择店铺**：新建/编辑商品时还不能选店（`ProductCreateDTO` 没加 shopId）；
4. **订单/支付/售后按店拆分**；
5. C 端「进入店铺」页：没有店铺主页，只显示名字。
