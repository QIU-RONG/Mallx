# Day 77 · 下单按店铺拆单

## 规则

- 购物车勾选的商品 **同一店铺 → 仍只生成一张订单**（老链路一行不变）；
- **跨店铺 → 每店生成一张订单**：各自金额、各自明细、各自延迟关单消息；
  接口统一返回 **订单 id 数组**（单店也返回长度为 1 的数组）；
- 多店拆单时**暂不支持优惠券**（券按整单门槛算，拆开后无法公平分摊）→ 400 人话；
- 库存扣减仍按 skuId 全局升序执行，然后再逐店插单 —— 避免多事务交叉死锁。

## 实现要点

- selectSelectedCartItems 增加 p.shop_id，OrderItemSourceVO 新增 shopId；
- 抽了三个私有方法：insertOrder / insertItems，单店与拆单共用，避免两份装配代码分叉；
- 拆单后每张订单都注册自己的 fterCommit 延迟关单消息；
- 前端结算页：ids.length > 1 时提示「已拆分为 N 个订单，请分别支付」并跳到订单列表；
  单店保持原行为（直接进详情页）。

## 验证

- 购物车放 iPhone（Apple 店）+ Huawei（MallX 自营）→ 下单返回 [21, 22]，
  两张单各只含本店商品、金额分别 9999 / 6999；
- 商户端订单列表只看到自己那张（21），看不到另一张（22）；
- 主链路 e2e **40/40**（脚本已适配数组返回值）；
- 顺带修：C 端/管理端状态映射缺 REFUNDED，之前订单列表遇到已退款单会渲染报错、一直转圈。

## 边界

1. 支付仍需逐单支付（前端跳列表让用户逐张付），没有「合并支付」；
2. 拆单后优惠券不可用；
3. 售后仍按整单，不按拆后的子单自动带出。
