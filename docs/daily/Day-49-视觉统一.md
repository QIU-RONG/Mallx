# Day 49 · 视觉统一：主色只能有一个来源

> 起因：一句话反馈 ——「好丑」。
> 这句反馈很主观，但**查下去发现的问题一点也不主观**：页面里同时跑着两套主色。
> 本文件记录怎么定位、怎么修、以及怎么防止它再漂。

---

## 一、诊断：不是「不够好看」，是自相矛盾

上一轮（Day 48 第三批）我按「补短板」的思路逐点打补丁：补价格、补筛选 chips、补骨架屏、
补品牌方块、补过渡动画。**每个补丁单看都对，合起来成了缝合怪。** 根因是四类：

### 病根一：两套主色同屏（最致命）

```css
/* theme.css 里定义了品牌色 */
--brand-color: #ff6a00;

/* 但全项目【没有一处】覆盖 --el-color-primary */
```

于是同一个页面里：

| 走我的橙色 `#ff6a00` | 走 EP 默认蓝 `#409eff` |
|---|---|
| 品牌方块、品牌名 | **搜索按钮** |
| 菜单选中 | **加入购物车按钮** |
| 价格 | **分页当前页** |
| 「查看详情 →」 | 输入框聚焦边框、筛选 tag |

橙与蓝同屏互抢。**最讽刺的一处**：`App.vue:116` 的注释里我自己写着
「EP 默认是蓝的，和橙色品牌打架」—— 看见了，但只改了菜单这一处。

### 病根二：深色侧栏里菜单「隐身」

`Layout.vue` 把侧栏背景刷成 `#1f2430`，却没有设 `--el-menu-text-color`。
Element Plus 的默认菜单文字是 `#303133`（深灰）—— 铺在深底上几乎看不见。

### 病根三：顶栏一屏五种颜色

品牌橙 `#ff6a00` + 购物车 `type="warning"` 琥珀 `#e6a23c` + 登录 `primary` 蓝
+ 退出 `danger` 红 + 分隔灰。没有主次，全在喊。

### 病根四：一张卡片三个 CTA

整卡可点进详情 + hover 浮出的「查看详情 →」+「加入购物车」按钮 —— 三个入口互相抢。

## 二、修法：主色收敛到**一个来源**

### 2.1 主色定为深靛蓝，并覆盖 EP 全套色阶

```
--el-color-primary:        #3b5bdb
--el-color-primary-light-3 #768ce6
--el-color-primary-light-5 #9daded
--el-color-primary-light-7 #c4cef4
--el-color-primary-light-8 #d8def8
--el-color-primary-light-9 #ebeffb
--el-color-primary-dark-2  #2f49af
```

★★ **六个数必须成套改**。Element Plus 的色阶有固定生成规律：

```
light-N = 主色 + (255 - 主色) × N/10
dark-2  = 主色 × 0.8
```

**只手改 `--el-color-primary` 的典型症状是「按钮 hover 时跳回蓝色」** ——
因为 hover 取的是 `light-3`。这个错只改一个值、静态截图还看不出来，最容易漏。

覆盖而不是逐个组件压 `!important`：**变量是官方入口**，
一次覆盖后按钮 / 链接 / 分页 / 输入框 / tag / 单选框全部自动跟随。

### 2.2 价格色与品牌色**分开**

```
--brand-price: #e1251b   /* 暖红 */
```

价格是**信息**，按钮是**操作**。同色会让用户扫一屏时把两者混为一谈。
暖红也更贴合国内电商的扫价习惯（注意：涨红跌绿，见项目约定）。

### 2.3 其余收敛

- 顶栏：购物车从 `warning`（琥珀）改回 `primary` link；品牌方块去掉常驻的彩色光晕
- 深色侧栏：显式给 EP 的菜单变量（`--el-menu-text-color` 等），选中项加 3px 左侧指示条
- 商品卡片：三个 CTA 砍成一个；价格从「和按钮同一行」里拿出来（18px 红字紧贴主色按钮，
  两者都在喊反而都不突出）
- 详情页：写死的 `#fff7f0` 橙底 → `var(--el-color-primary-light-9)`
- 管理端 Dashboard：SVG 里写死的 `#409eff` / `#79bbff` → CSS 变量

## 三、验收

| 项 | 结果 |
|---|---|
| mall-app `eslint --max-warnings 0` | 0 问题 |
| mall-app `vue-tsc + vite build` | 成功 |
| mall-app Vitest | 15 passed |
| admin-app `vue-tsc + vite build` | 成功 |
| **dist 产物里 `--el-color-primary` 的定义顺序** | 共 2 处，**末个 = `#3b5bdb`** ⇒ 覆盖生效 |

★ 最后一条是**产物级**验证，比看源码有意义得多：CSS 变量的胜负取决于同选择器下的
**先后顺序**，而 Vite 会合并压缩所有 CSS。若我的 `:root` 块被排到 Element Plus 之前，
浏览器仍会用蓝色，而 **eslint / vue-tsc / build 全都不报错**。
所以判据必须落到「产物里最后一个定义是谁」。

## 四、护栏：`day49-theme-guard.py`（6 条，纯静态，进 CI）

| 断言 | 拦什么 |
|---|---|
| A1 | 两个应用的 `--el-color-primary` 都存在且同值（两套主色是「看着乱」第一来源） |
| **A2** | **★ 六个色阶成套，且与主色按 EP 混色公式同源** |
| A3 | `--brand-color` 与 `--el-color-primary` 同值（防止又分叉） |
| A4 | `theme.css` 的 import 排在 EP 样式之后（否则覆盖静默失效） |
| B1 | 源码非注释区没有残留的旧橙色 / EP 默认蓝 |
| B2 | 两个应用的 `--brand-price` 同值 |

**A2 是唯一用公式推导的**：它不比对「我写的值」，而是从主色算出六个色阶再比。
这样才能抓住「只手改 primary」。

### 控制组：`_d49_theme_ctrl.py`（6 组变异，全部命中且零误伤）

| 变异 | 期望命中 |
|---|---|
| ① 删掉 EP 覆盖（＝上一版的状态） | A1 + A2 + A3 |
| ② 只把 light-3 改回 EP 的 `#79bbff` | A2（**实际还多命中 B1** —— 引入 EP 蓝本就该被看见） |
| ③ 两应用品牌色分叉 | A3 |
| ④ 调换 import 顺序 | A4 |
| ⑤ 留一个硬编码 EP 蓝 | B1 |
| ⑥ 两应用价格色分叉 | B2 |

## 五、这一轮踩到的两个坑

### 坑 1：护栏第一次跑就红 5 条，但**红的是护栏自己**

我把路径写漏了 `frontend/` 前缀，于是所有文件都读不到 ⇒ 5 条断言全报「缺失」。
**症状看起来像「主题全面漂移」**，实际是环境错误伪装成业务错误 —— 最误导的一种红。

⇒ 已加**前提护栏**：文件读不到时判 `rc=2`、明确输出「这是路径/环境问题，不是主题漂移」，
与「断言失败」（rc=1）分开。

### 坑 2：控制组把「本轮真实改动」误报成「还原不干净」

控制组结尾用 `git status` 复核，只要工作区非空就判 FAIL。但控制组通常在
**改动还没提交**时跑，那时工作区本来就是脏的（本轮 8 个文件）。

⇒ 判据改成**集合差**：先记一次基线，最后比「有没有【多出来】的改动」（＝变异残留）。

## 六、留下的规矩

1. **主色只能有一个来源。** 加品牌色时，必须同时覆盖 Element Plus 的七个变量（六色阶 + primary）。
2. **价格与操作不同色。** 金额一律 `--brand-price`。
3. **手写 SVG / canvas 的颜色也必须走 CSS 变量** —— 它们不跟主题走，光看代码极难发现。
4. 深色底上的 EP 组件，**必须显式给文字色变量**（默认值是给白底用的）。
