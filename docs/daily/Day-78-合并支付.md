# Day 78 · 拆单后的合并支付

## 做了什么

- 新增 POST /api/payments/batch：body { orderIds: [...], method }，一次付清多张待支付订单；
- 逐单复用 PaymentService.pay（归属校验 / CAS 抢资格 / 库存 locked→sold 全都不绕过），
  整批在<b>同一事务</b>里，任何一张失败全部回滚；
- 金额服务端累加（不接收客户端金额）；去重后一次最多 20 张；
- 前端结算页：跨店拆单后自动调用批量支付，提示「已拆分为 N 个订单并完成支付」→ 订单列表；
  单店仍保持原流程（进订单详情、由用户点支付）。

## 验证（实测）

| 项 | 结果 |
|---|---|
| 跨店下单 | ids=[24,25] |
| 批量支付 | 200，count=2，totalAmount=33996 |
| 两单状态 | 均 PAID |
| 重复批量支付 | 400「订单状态不允许支付」 |
| 主链路 e2e | 40/40 |

## 环境事故记录

测试前发现 **临时 PG 集群（5434）已停止**（机器闲置后进程消失），后端一直 503。
用 pg_ctl -D %TEMP%\\mallx-pg -o \"-p 5434\" start 拉起后恢复正常（自动 WAL recovery 成功）。
★ 这台机器上的 MySQL/PG/Redis 都是手工临时进程，重启后需要按文档重新拉起；
后端 Hikari 在数据库恢复后无需重启即可继续工作。

## 边界

1. 批量支付失败时整批回滚（不会出现「付了两张、第三张失败」）；
2. 不支持混合支付方式（整批一个 method）；
3. 拆单后优惠券仍不可用（Day 77 的取舍）。
