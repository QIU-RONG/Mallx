## 1. 为什么不给商品页加「写评价」

评价必须绑定**订单明细**（`orderItemId`），后端据此校验三件事：

1. 这条明细是**你的**；
2. 订单状态是 **COMPLETED**；
3. 一条明细只能评一次（`uk_reviews_order_item` 唯一约束）。

商品页没有「订单明细」这个上下文，硬加输入框只会让用户写完吃 400
（「只有已完成的订单才能评价」）。⇒ 写评价只能从**订单详情**进入；
商品页只做展示。这也是真实商城的通行做法。

## 2. 三处界面

### 商品详情（`ProductDetail.vue`）

- 标题右侧是聚合：`el-rate` + 平均分 + 「N 条评价」（来自 `ReviewPageVO.avgRating/reviewCount`）；
- 列表每条：昵称首字圆形头像、昵称、星级、时间、内容；
- 「查看更多评价（x / y）」每次 +5 条 —— 用现有分页接口，不做一次拉全量；
- 空态文案是「还没有评价，买过的人可以说两句」，不是冷冰冰的「暂无数据」；
- ★ 评价加载失败不阻塞商品主体：`loadReviews` 在 `productDetail` 之后单独调用。

### 订单详情（`OrderDetail.vue`）

- 只有 `COMPLETED` 的订单才出现「评价」列 —— 前端不给注定失败的按钮；
- 弹窗：商品缩略图 + 名称/规格 + `el-rate` + 500 字输入框；
- 提交后弹「评价成功」；重复评价由后端返回「该商品已评价过」，拦截器统一提示。

### 我的评价（`MyReviews.vue`）

- 路由 `/account/reviews`，左侧导航加「我的评价」；
- 每行：商品缩略图（点进商品页）、名称、规格、星级、内容、时间；
- 归属条件在后端 SQL 里（`WHERE user_id = ?`），前端不传 userId。

## 3. 一个顺手修掉的数据问题

截图时发现评价人昵称显示成 `????`。查下来不是编码 bug，而是**我自己的测试污染**：
Day 58 验「改昵称」时用 PowerShell 的 `Invoke-RestMethod` 发中文 JSON，
没带 charset，它按 ANSI 编码 —— 4 个汉字变成了 4 个问号写进库。

★ 已用 UTF-8 请求把昵称改回「演示用户」。
★ 教训与 Day 59 第 2 条同源：**中文 JSON 的验证一律用 Python / UTF-8**，
PowerShell 的 `Invoke-RestMethod` 不能用来发含中文的请求体。
