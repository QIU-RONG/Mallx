# Day 63 · 个人中心概览改版（以商品为主体 + 图形引导）

> 需求原话：**「对于客户的个人中心应该直接看到的是商品，而不是订单编号，还可以加一些图案，让客户更好理解」**。

---

## 0. 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 最近订单 | `MX2026...` 订单号 + 状态 + 金额 | **商品缩略图 + 商品名 + 规格**（多件显示「等 N 件」）+ 状态 + 实付 |
| 订单号 | 首屏主体 | 完全移除（要查单号去订单详情） |
| 四个数字 | 纯数字卡片 | 每个配一个线性图标（钱包 / 卡车 / 盾牌 / 券） |
| 快捷入口 | 无 | 我的订单 / 退款售后 / 优惠券 / 收货地址，各带图标 |

## 1. 为什么订单列表接口不够用

`GET /api/orders` 返回的 `OrderVO` **没有明细**（只有订单头：单号、状态、金额、收货人）。
要展示「买了什么」，有两条路：

1. 改后端，让列表带首件商品 —— 动的是被 M1 覆盖的 VO，代价大；
2. 前端对最近 3 单各查一次 `GET /api/orders/{id}`，取 `items[0]`。

选了 ②：3 个并发请求换「一眼看懂」，对概览页是划算的。
★ 但如果哪天要做「最近 20 单」，就必须回到 ①（VO 加字段），不能 N+1 拉到 20 次。

## 2. 图形怎么用

- 图标全部是**内联 SVG**（`stroke-width: 1.6`），不用图标库：少一个依赖，风格也和现在的线条一致；
- 图标放在浅灰圆角块里，只承担「这是哪一类」的识别，不抢数字；
- 状态用 `el-tag` 的语义色 + 文字，不靠颜色单传信息（色弱用户也能读）。

## 3. 验证

| 项 | 结果 |
|---|---|
| `npm run lint` / `build` | 0 警告 / 通过 |
| 概览页截图 | 3 条最近订单均显示商品缩略图、名称、规格、件数、金额；图标正常 |
| 主链路 e2e | 40/40（后端零改动，随时可复跑） |

## 4. 没做的

1. **订单列表页**仍以单号为主（列表页是对账视角，保留单号合理）；如果要统一，改成「商品图 + 名称」只是同一套组件复用；
2. 商品缩略图仍是占位渐变（`oss.mallx.local` 不存在）；
3. 统计数字（待付款/待收货）在没有对应订单时显示 0 —— 暂无「空态引导」（例如 0 时点击仍进订单列表）。
